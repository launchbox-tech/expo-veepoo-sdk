# 1.3.1 — VeepooBleSDK.framework 2.2.66.15 → 2.2.88.15 (iOS) + exercise read via the typed sport API

## Why

Band-recorded workouts were unreadable on iOS. Six instrumented device runs
(2026-06-06) proved that on 2.2.66.15:

- the legacy `Start` transfer reads sessions (`3/3 → complete`) but persists
  nothing `veepooSDKGetDeviceRunningDataWithDate` can see, and
- the CRC/block tier (`veepooSDK_readDeviceRunningCrcResult`,
  `…readDeviceRunningDataWithBlockNumber`) is a stub — its header section is
  marked "implemented by subclass VPPeripheralAddManage, temporarily not
  implemented".

Upstream `HBandSDK/iOS_Ble_SDK` shipped **2.2.88.15** (2026-06-03) with the
typed sport API — the iOS mirror of Android's `readSportModelOrigin`:
`readDeviceSportCRCArr` → `readDeviceSportWithCRC` →
`VPDeviceSportModel[]` / `VPDeviceSportWithGPSModel[]`.

## Changes

- `ios/VeepooSDK/Frameworks/VeepooBleSDK.framework` → **2.2.88.15** (arm64).
  - The bundled binary `VeepooBleSDK.swiftmodule` is **deliberately removed**:
    it is compiler-version-locked (built with Swift 6.2.3, breaks under any
    other toolchain) and ships no `.swiftinterface`. The framework's Swift
    surface remains available through the ObjC projection
    (`VeepooBleSDK-Swift.h`, declared in the modulemap). Re-apply this
    removal on every future framework bump.
- `VeepooSDKModule+Exercise.swift`: exercise read now uses the typed sport
  API as the primary path (10s CRC watchdog, 60s detail watchdog); legacy
  `Start` + DB sweep retained as fallback for app-started legacy sessions;
  the stubbed CRC/block probe is removed. Units normalized at the boundary
  (ADR-0016): new API totals are m + kcal; legacy DB is m + cal; JS contract
  stays km + kcal.
- `vendor-manifest.json`: `ios.veepooBleSdkVersion` 2.2.88.15,
  `lastReviewedHeadSha` cc8c058.

## Verification

- Full VeepooSDK pod device-compiles (`-sdk iphoneos`) against 2.2.88.15.
- JS suite: 895 tests green; no TS surface changes in this bump.
- Device verification (band-recorded sessions landing via `sport-api` read
  path) tracked in the host app.
